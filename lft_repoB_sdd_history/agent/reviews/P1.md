# P1 Review Findings

### FastWAM temporal RoPE uses 30 FPS instead of the sampled 5 FPS

- Severity: P1
- Status: Open
- File: [model_utils.py](../../ge_act/utils/model_utils.py#L173)
- Problem: `forward_pass` defaults `frame_rate` to 30 and the trainer never overrides it. LIBERO source videos are 20 FPS, while the FastWAM config samples 9 video frames from 36 action frames, giving stride 4 and an effective video rate of 5 FPS.
- Impact: LTX query RoPE encodes a temporal scale six times too fast. A semantic key RoPE built from the correct timestamps would then be inconsistent with the query RoPE; reusing the current default for both would remain physically wrong.
- Evidence: All four local LIBERO FastWAM `meta/info.json` files report `fps=20`; config values `chunk=9` and `action_chunk=36` imply `20 / (36/9) = 5` FPS. Training reaches `forward_pass` without a `frame_rate` argument at `ge_trainer.py:657-674`.

### Existing LTX cross-attention processor cannot implement same-camera semantic injection

- Severity: P1
- Status: Open
- File: [transformer_ltx_multiview.py](../../ge_act/models/ltx_models/transformer_ltx_multiview.py#L108)
- Problem: Whenever `image_rotary_emb` is absent, the shared processor concatenates every view's query sequence into batch `B`, while leaving keys and values in the encoder batch layout. Supplying view-specific semantic context as `[B*V,L,D]` would therefore produce incompatible or broadcast batch dimensions and would not preserve direct same-camera attention.
- Impact: Reusing `attn2`'s processor for SigLIP2 either crashes for ordinary batches or silently mixes/broadcasts views. A dedicated processor with separate query/key RoPE and no view rearrangement is required.
- Evidence: Lines 108-110 rearrange only `query` from `(b v)` to `b`; keys and values remain as projected from `encoder_hidden_states`. The later split at lines 124-125 assumes the text-context contract rather than a view-specific context contract.

### Current optimizer cannot express safe joint-finetuning learning rates

- Severity: P1
- Status: Open
- File: [ge_trainer.py](../../ge_act/runner/ge_trainer.py#L399)
- Problem: All non-action video parameters are collected into one optimizer group and receive the same learning rate. The current FastWAM config sets that rate to `3e-4`, which would also be applied to the pretrained 1.95B-parameter LTX tower after semantic modules are added.
- Impact: The requested full LTX joint training cannot use a conservative base LR and a larger new-module LR; using the current configuration risks destructive pretrained-weight updates, while lowering the single LR under-trains the cold semantic branch.
- Evidence: Lines 399-428 construct exactly one parameter group. The current config sets `lr: 3e-4`; the reviewed design requires separate groups for base LTX and `semantic_*` parameters.

### Saved checkpoint directories are not loadable through the advertised directory path

- Severity: P1
- Status: Open
- File: [model_utils.py](../../ge_act/utils/model_utils.py#L63)
- Problem: A directory checkpoint is always interpreted as a sharded checkpoint containing `diffusion_pytorch_model.safetensors.index.json`, but `save_pretrained` commonly writes a single `diffusion_pytorch_model.safetensors` file.
- Impact: Passing a saved `step_N/` directory back to training or inference fails even though that directory is produced by this trainer. The larger semantic model is still expected to fit under Diffusers' default single-file shard limit in BF16.
- Evidence: Lines 64-65 unconditionally open the index for any directory, while `ge_trainer.py:758-759` calls `save_pretrained` without forcing sharding. The project README describes single-file `step_N` outputs.

### Oracle semantic validation and deployable inference have no explicit contract

- Severity: P1
- Status: Open
- File: [custom_pipeline.py](../../ge_act/models/pipeline/custom_pipeline.py#L563)
- Problem: The pipeline accepts only image/text/action inputs and the denoising call never forwards semantic features or semantic times. Training on online ground-truth future SigLIP2 features therefore has no corresponding validation path, no classifier-free-guidance duplication rule, and no external planner input contract.
- Impact: Validation would silently measure the no-semantic model path, or an ad-hoc implementation could leak/misorder camera features. A checkpoint could train successfully yet be unusable with the VLM planner.
- Evidence: The `infer` signature at lines 563-600 has no semantic arguments, and the transformer call at lines 879-900 forwards none. The trainer validation only passes memory frames at `ge_trainer.py:800-845`.

### Ground-truth and existing planner keyframe conventions are not aligned

- Severity: P1
- Status: Open
- File: [train_qwen3vl4b_lingbot_dino_planner.py](../../qwen3_vl_semantic_planner/train_qwen3vl4b_lingbot_dino_planner.py#L512)
- Problem: Uniformly selecting four frames from GE-Act's nine future frames gives future indices `[0,3,5,8]`. The existing planner treats a nine-frame sequence as one current plus eight future frames, producing `[1,3,6,8]` for `uniform` or `[2,4,6,8]` for `even_future`.
- Impact: Planner tokens can be dimensionally correct but refer to different horizons than the world model's oracle targets; their temporal coordinate/semantic meaning would be wrong at deployment.
- Evidence: Lines 519-536 define the planner offsets over `[1,T-1]`. The GE-Act dataset already splits four memory frames from a separate nine-frame future tensor, so its zero-based future selection is a different contract.

### All-layer native-grid semantic attention materially changes the model and batch budget

- Severity: P1
- Status: Open
- File: [transformer_ltx_multiview.py](../../ge_act/models/ltx_models/transformer_ltx_multiview.py#L407)
- Problem: Adding full 2048-d semantic cross-attention to all 28 blocks plus a Cosmos-style rank-256 semantic AdaLN adds approximately 535,536,640 parameters to the 1,948,569,728-parameter LTX model, before the frozen SigLIP2 tower is placed on each GPU.
- Impact: The current per-GPU batch size 16 is not a safe launch assumption. The semantic branch adds about 27.5% parameters and a 1024-key attention operation in every block, so a smoke run must establish batch size and throughput before setting global batch or duration.
- Evidence: Counts were computed directly from the current 28-layer, 2048-d config on the meta device: semantic attention 469,991,424; rank-256 modulation 58,720,256; adapter/coords/type 6,824,960.
